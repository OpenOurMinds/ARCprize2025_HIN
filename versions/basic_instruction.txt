## **Deep Dive: Strategies for Multi-Array State Representation in Reinforcement Learning**

In Reinforcement Learning, the "state" is the agent's observation of its environment at a given time. Often, this observation comes in the form of a multi-dimensional array (e.g., a 2D grid, a 3D volume, or a sequence of such structures). Effectively processing this multi-array state is crucial for an RL agent to learn optimal policies. This document explores common strategies for representing and processing multi-array states, from simple direct use to advanced deep learning techniques.

---

### **1. Direct Use for Small, Discrete State Spaces**

**Concept:** When the multi-array represents a simple, discrete environment with a manageable number of unique configurations, it can be used directly as the state. This approach relies on the ability to uniquely identify and store information for each distinct state.

**Explanation:**
For environments where the number of possible multi-array configurations is relatively small, the agent can treat each unique multi-array as a distinct state. This is often the simplest approach and works well for foundational RL algorithms.

*   **Grid Worlds:**
    *   **Description:** A classic example where an agent navigates a 2D grid. The multi-array (e.g., a NumPy array) represents the entire grid.
    *   **Representation:** Integer values within the array typically encode different entities: `0` for empty space, `1` for the agent's position, `2` for an obstacle, `3` for a reward, etc.
    *   **Example:** A `(5, 5)` NumPy array where `state[x, y] = 1` if the agent is at `(x, y)`.
*   **Tabular Q-learning:**
    *   **Description:** This method stores a Q-value (expected future reward) for every possible state-action pair in a "Q-table."
    *   **Application with Multi-Arrays:** To use a multi-array state in tabular Q-learning, each unique multi-array configuration must be mapped to a discrete index or key.
        *   **Hashing:** You can convert the multi-array (e.g., a NumPy array) into a hashable type (like a tuple of tuples if it's 2D, or a flattened tuple) to use as keys in a dictionary (Python `dict`) that acts as your Q-table.
        *   **Direct Indexing:** If the multi-array dimensions are fixed and small, and the integer values are limited, you might be able to combine the elements into a single integer index.
    *   **Pros:** Guaranteed to find optimal policies (given sufficient exploration), simple to implement for small problems.
    *   **Cons:** Suffers from the "curse of dimensionality"; the Q-table grows exponentially with the number of possible states, quickly becoming unfeasible for larger or more complex grids.

---

### **2. Flattening the Array for Feature Vectors**

**Concept:** For deep learning approaches that utilize dense (fully connected) neural networks, a multi-array state can be converted into a one-dimensional feature vector.

**Explanation:**
This method transforms the structured multi-array into a flat sequence of numbers, suitable for input into a standard feed-forward neural network.

*   **Process:**
    1.  **Conversion:** A multi-array with dimensions like `(rows, cols, channels)` (e.g., a `(10, 10, 1)` grid) is reshaped into a single 1D vector (e.g., `(rows * cols * channels)` which would be `(100,)`).
    2.  **Input:** This 1D vector is then fed directly as the input layer to a standard feed-forward (dense) neural network. Each element of the vector becomes an input feature.
*   **Considerations:**
    *   **Spatial Relationship Loss:** The primary drawback is that flattening inherently discards spatial relationships (e.g., adjacency, proximity) between elements in the multi-array. If these spatial patterns are crucial for the task (as they are in image-like data), this approach can significantly degrade performance.
    *   **Effectiveness:** This approach is most effective when:
        *   Spatial features are less critical than individual values.
        *   The array is small enough that a dense network can still implicitly capture relevant information without being overwhelmed by parameters.
    *   **Pros:** Simplicity in network architecture, compatible with various standard neural network designs.
    *   **Cons:** Ignores valuable spatial context, scales poorly to larger arrays due to the increasing number of input features and network parameters.
    *   **Use Cases:** Simple sensor arrays where sensor values are important but their spatial arrangement is less so, or very small grid-like observations.

---

### **3. Using a Convolutional Neural Network (CNN)**

**Concept:** When a multi-array has a grid-like structure with crucial spatial relationships, a Convolutional Neural Network (CNN) is typically the most powerful and appropriate choice for processing the state.

**Explanation:**
CNNs are purpose-built for processing data with a grid-like topology, such as images. They excel at automatically learning hierarchical spatial features.

*   **Analogy to Images:**
    *   **Treatment:** The multi-array is treated much like an image. Each integer value at a particular `(x, y)` location in the array can represent a "pixel value" or a specific feature (e.g., terrain type, object ID, agent presence).
    *   **Channels:** For simple integer grids, you might have one "channel" of data. If each grid cell can have multiple attributes (e.g., type of ground, presence of item, temperature), these could be represented as different channels.
*   **Process:**
    1.  **Direct Input:** The multi-array is fed directly into the input layer of a CNN. It typically needs a shape like `(Batch, Height, Width, Channels)`.
    2.  **Feature Extraction:** Convolutional filters (kernels) slide across the input, detecting local patterns (edges, textures, shapes). Pooling layers then reduce dimensionality while preserving important features. This process automatically learns and extracts meaningful spatial features.
    3.  **Output:** The extracted features from the final convolutional/pooling layers are often flattened and then fed into one or more dense layers. These dense layers then typically output the Q-values for each possible action, or parameters for a policy.
*   **Example: Chess AI:**
    *   **Representation:** A chess board can be represented as an `(8, 8, N)` multi-array, where `N` channels encode information like piece type, color, legal moves, etc., at each square.
    *   **CNN Benefits:** A CNN would be ideal for learning complex spatial patterns such as checkmate setups, pawn structures, threats, and defensive formations, which are distributed across the board.
*   **Pros:** Automatically learns relevant spatial features, preserves spatial relationships, parameter sharing (filters apply across the entire input) makes them efficient and robust to translations, highly effective for visual or grid-based environments.
*   **Cons:** Requires more computational resources than flattening, might be overkill for environments where spatial relationships are truly insignificant.
*   **Use Cases:** Video games, robotics with camera inputs, visual navigation, any environment where the spatial arrangement of elements is critical.

---

### **4. Sequence Models for Temporal Data**

**Concept:** If the multi-array data has a temporal component (meaning the agent's state is not just the current observation, but a sequence of observations over time), recurrent neural networks (RNNs) or Long Short-Term Memory (LSTM) networks are appropriate.

**Explanation:**
Many real-world environments are partially observable or dynamic, meaning a single snapshot (multi-array) isn't enough to fully understand the situation. The agent needs to consider a history of states.

*   **Temporal Component:** This refers to a series of multi-arrays observed over time (e.g., `[state_t-N, ..., state_t-1, state_t]`). The agent's decision at time `t` depends not only on `state_t` but also on the sequence leading up to it.
*   **RNNs/LSTMs:** These neural network architectures are designed to process sequential data. They maintain an internal "hidden state" that acts as a memory, allowing them to capture dependencies across different time steps.
    *   **Process:** Each multi-array in the sequence is typically first processed by a CNN (if it has spatial structure) to extract features. These extracted feature vectors are then fed sequentially into an RNN/LSTM layer. The output of the RNN/LSTM at the final time step or aggregated across steps can then inform the agent's policy.
*   **Multi-View RL:**
    *   **Description:** In scenarios where observations come from multiple sources (e.g., different camera angles, various sensor types) and are time-dependent, sequence models become even more critical.
    *   **Processing:** Data from different "views" (each potentially a multi-array) might be processed separately by their own CNNs or other feature extractors. The resulting feature vectors are then combined (e.g., concatenated) and fed into an RNN/LSTM to synthesize a comprehensive temporal understanding of the environment. This combined representation then informs the agent's policy.
*   **Pros:** Essential for environments requiring memory or handling partially observable states, capable of learning complex temporal dependencies.
*   **Cons:** More complex to train (vanishing/exploding gradients for vanilla RNNs), requires careful handling of sequence length and statefulness.
*   **Use Cases:** Autonomous driving (processing video streams over time), game AI needing memory of past turns/observations, robotics with dynamic sensor readings, poker AI considering opponent's actions history.

---

### **5. State Representation Learning (SRL)**

**Concept:** For particularly complex or high-dimensional environments (e.g., raw images, physics simulations), an agent can learn a compact, low-dimensional, and often more abstract representation of the multi-array state *before* performing the main RL task.

**Explanation:**
SRL aims to transform the raw, high-dimensional observations into a more meaningful and efficient representation, making the RL task easier to learn. This often involves an unsupervised or self-supervised pre-training step.

*   **Process:**
    1.  **Representation Network:** An auxiliary neural network (e.g., an autoencoder, variational autoencoder (VAE), or generative adversarial network (GAN)) is trained.
    2.  **Compression:** This network learns to compress the high-dimensional multi-array data into a lower-dimensional **latent space** (a compact vector of features). For an autoencoder, this involves training the network to reconstruct the input from its compressed representation.
    3.  **RL Agent Input:** The RL agent then uses this compressed, low-dimensional latent vector as its state instead of the raw multi-array. This smaller, more abstract state is typically easier for the RL policy network to learn from.
*   **Benefits:**
    *   **Improved Sample Efficiency:** The RL agent learns faster with a simpler, more informative state space.
    *   **Better Generalization:** A well-learned representation can disentangle relevant features from irrelevant noise, leading to better generalization across different scenarios.
    *   **Reduced Dimensionality:** Overcomes the curse of dimensionality by providing a compact state.
    *   **Interpretability (sometimes):** A disentangled latent space can sometimes offer insights into what features the model considers important.
*   **Pros:** Addresses high-dimensionality, improves learning efficiency and generalization, can learn abstract features.
*   **Cons:** Adds complexity by requiring an additional representation learning phase (pre-training or concurrent training), the quality of the RL performance heavily depends on the quality of the learned representation.
*   **Use Cases:** Environments with raw image/video inputs, robotics with complex sensor data, environments where defining hand-crafted features is difficult.

### **Implementation Example: CNN with a Multi-Array State (Grid World)**

Let's illustrate how a Convolutional Neural Network (CNN) would process a 2D integer array, typical of a grid world environment, within a deep reinforcement learning setup.

**1. Environment:**
The environment (`env`) would have a `step()` function that takes an action and returns the new state (a multi-array observation), reward, and whether the episode is done. It would also have a way to retrieve the current full observation, e.g., `env.get_state()`.

**Example State:** A `(10, 10)` NumPy array where each cell contains an integer (e.g., `0` for empty, `1` for agent, `2` for wall, `3` for goal).

**2. State Representation:**
The observation from the environment is a multi-array, specifically a 2D NumPy array of integers. For a CNN, we typically need to reshape this into `(Batch, Height, Width, Channels)`. Since our grid has a single type of information (e.g., "what's in this cell"), it will have 1 channel.

**3. Agent's Neural Network (Q-Network Example):**
This is a simple deep neural network that takes the multi-array state as input and outputs Q-values for each possible action.

```python
import tensorflow as tf
from tensorflow.keras.layers import Conv2D, Flatten, Dense
from tensorflow.keras.models import Sequential
import numpy as np # For state manipulation

# --- Configuration ---
grid_height = 10
grid_width = 10
num_actions = 4 # Example: Up, Down, Left, Right

# --- Neural Network Model Definition ---
model = Sequential()
# Input layer: Conv2D expects (height, width, channels) for single input,
# but it will receive (batch, height, width, channels) during actual prediction.
# Here, '1' indicates a single channel (e.g., integer values representing cell types).
model.add(Conv2D(32, (3, 3), activation='relu', input_shape=(grid_height, grid_width, 1)))
# Another convolutional layer to extract more complex features
model.add(Conv2D(64, (3, 3), activation='relu'))
# Flatten the output of the convolutional layers into a 1D vector
model.add(Flatten())
# A dense hidden layer for further processing
model.add(Dense(128, activation='relu'))
# Output layer: Produces Q-values for each action. 'linear' activation is standard for Q-values.
model.add(Dense(num_actions, activation='linear'))

model.summary()
```

**Explanation of Model Layers:**

*   **`Conv2D(32, (3, 3), activation='relu', input_shape=(grid_height, grid_width, 1))`**:
    *   This is the first convolutional layer. It has `32` filters, each `3x3` in size.
    *   `activation='relu'` applies the Rectified Linear Unit activation function.
    *   `input_shape=(grid_height, grid_width, 1)` defines the expected shape of a single input state (e.g., `(10, 10, 1)` for a 10x10 grid with one channel).
*   **`Conv2D(64, (3, 3), activation='relu')`**:
    *   Another convolutional layer, often with more filters (`64`) to learn more complex patterns from the features extracted by the previous layer.
*   **`Flatten()`**:
    *   Converts the 3D output of the last `Conv2D` layer (e.g., `(H', W', Filters)`) into a 1D vector. This is necessary to feed it into the subsequent dense layers.
*   **`Dense(128, activation='relu')`**:
    *   A fully connected (dense) layer with `128` neurons, applying a `relu` activation. This layer processes the flattened features.
*   **`Dense(num_actions, activation='linear')`**:
    *   The output layer. It has `num_actions` neurons (e.g., 4 for our example).
    *   `activation='linear'` is used because Q-values can be any real number (positive or negative), unlike probabilities which might require `softmax`.

**4. Training Loop (Simplified):**
During actual training (e.g., using a Deep Q-Network - DQN), the agent's network receives the multi-array state, predicts Q-values, and chooses an action.

```python
# --- In the training loop (within your DQN agent or similar) ---

# Assume 'env' is your environment object that provides states
# And 'model' is the Keras model defined above

# 1. Get the current state (a multi-array, e.g., from env.reset() or env.step())
# Example: Create a dummy state for demonstration
state_multi_array = np.random.randint(0, 4, size=(grid_height, grid_width)) # 10x10 grid with values 0-3

# 2. Reshape the state to be compatible with the Conv2D layer
# The model expects input in the format (batch_size, height, width, channels)
state_tensor = tf.convert_to_tensor(state_multi_array, dtype=tf.float32) # Convert to tensor, specify dtype
state_input = tf.expand_dims(state_tensor, axis=0) # Add batch dimension (1, height, width)
state_input = tf.expand_dims(state_input, axis=-1) # Add channel dimension (1, height, width, 1)

# 3. Predict Q-values for all possible actions using the neural network
q_values = model.predict(state_input)
# q_values will be an array like [[Q_up, Q_down, Q_left, Q_right]]

# 4. Choose an action based on an exploration strategy (e.g., epsilon-greedy)
epsilon = 0.1 # Example exploration rate
if np.random.rand() < epsilon:
    action = np.random.randint(num_actions) # Explore: choose random action
else:
    action = np.argmax(q_values[0]) # Exploit: choose action with highest predicted Q-value

# 5. Proceed with the RL algorithm
# new_state, reward, done, info = env.step(action)
# Then update the Q-network using techniques like experience replay and target networks (common in DQN).
print(f"Current State (first 3 rows):\n{state_multi_array[:3,:]}")
print(f"Reshaped State Input Shape for CNN: {state_input.shape}")
print(f"Predicted Q-values: {q_values[0]}")
print(f"Chosen Action: {action}")

Tasks
ARC-AGI tasks are a series of three to five input and output tasks followed by a final task with only the input listed. Each task tests the utilization of a specific learned skill based on a minimal number of cognitive priors.

ARC-AGI task

In their native form, tasks are a JSON lists of integers. These JSON can also be represented visually as a grid of colors using an ARC-AGI task viewer. You can view an example of a task here.

A successful submission is a pixel-perfect description (color and position) of the final task's output.

ARC-AGI-2
2025 introduces a new version of ARC-AGI, ARC-AGI-2. This is the same format as ARC-AGI-1. All conventions of public/private/semi-private data still apply. For more on the new dataset, see the ARC-AGI-2.

100% of tasks in the ARC-AGI-2 dataset were solved by a minimim of 2 people in less than or equal to 2 attempts (many were solved more). ARC-AGI-2 is more difficult for AI.

We recommend using the ARC-AGI-1 dataset for getting started and then moving to ARC-AGI-2 for more advanced solutions. The remainder of this guide will focus on ARC-AGI-2.

Task Data
The following datasets are associated with the ARC Prize competition:

Public training set
Public evaluation set
Private evaluation set
Outside of the competition, there is also a semi-private evaluation set used for the public leaderboard. Learn more.

Public
The publicly available data is to be used for training and evaluation.

The public training set contains 1,000 task files you can use to train your algorithm.

The public evaluation set contains 120 task files for to test the performance of your algorithm.

To ensure fair evaluation results, be sure not to leak information from the evaluation set into your algorithm (e.g., by looking at the tasks in the evaluation set yourself during development, or by repeatedly modifying an algorithm while using its evaluation score as feedback.)

The source of truth for this data is available on the ARC-AGI GitHub Repository, which contains 1,120 total tasks.

Semi-Private
The semi-private evaluation set contains 120 task files.

The Semi-Private Evaluation set is 120 tasks which are privately held on Kaggle. These tasks are used for the intra-year competition standings. These tasks are not included in the public tasks, but they do use the same structure and cognitive priors.

These tasks are also used to measure public, closed-source model performance.

Private
The private evaluation set contains 120 task files.

The ARC-AGI leaderboard is measured using 120 private evaluation tasks which are also privately held on Kaggle. These tasks are private to ensure models may not be trained on them. These tasks are not included in the public tasks, but they do use the same structure and cognitive priors.

Please note that the public training set consists of simpler tasks whereas the public evaluation set is roughly the same level of difficulty as the private test set.

Set Difficulty
One of enhancements made with ARC-AGI-2 is the introduction of a difficulty calibration. Private Evaluation, Public Evaluation and Semi-Private Evaluation sets are now calibrated to be roughly the same difficulty (<1pp) as measured by human & AI performance.

Format
As mentioned above, tasks are stored in JSON format. Each JSON file consists of two key-value pairs.

train: a list of two to ten input/output pairs (typically three.) These are used for your algorithm to infer a rule.

test: a list of one to three input/output pairs (typically one.) Your model should apply the inferred rule from the train set and construct an output solution. You will have access to the output test solution on the public data. The output solution on the private evaluation set will not be revealed.
